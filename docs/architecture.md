# 網站整體架構與缺漏（討論稿）

> 狀態：討論中，尚未定案。本分支只放文件，不改網站內容；合併到 main 前需老師確認。
> 起點：2026-11-10 光學單元動態解析與整體架構討論。

## 1. 目的

把目前分散的元件（知識圖譜、互動式教具、題庫、素養題、數位詳解）放到同一張架構圖上，找出彼此之間缺少的連結，並決定建置順序。

結論先講：缺漏主要不在內容本身，而在把內容串起來的三個地方：**共用索引、題目屬性、資料迴路**。

## 2. 三層架構

| 層 | 元件 | 本站現況 |
|---|---|---|
| 內容層 | 互動式教具 | 放在舊站 `CWKuo99/test`，本站以絕對網址連結（`sims`）。教具各自獨立，尚未抽出可重用的引擎。 |
| | 題庫 | `data/questions/<課綱代碼>.json`，只有 L0～L2 選擇題與預測題。 |
| | 數位詳解 | 目前只有每個錯誤選項的 `why`。逐步動態解析尚無位置。 |
| | 實驗與學習單 | 尚無位置（見第 5 節）。 |
| 共用索引 | 知識成分 KC | `data/curriculum.json`：主軸 → 課綱代碼 → kc，已上線。 |
| | 招式（程序性判斷規則） | **缺**。 |
| | 迷思詞表 | **缺**。`mis` 目前是自由文字（見 4.3）。 |
| 資料迴路 | 作答回傳 | 已有：`gas/Code.gs`，學生填班級與座號。 |
| | 學習紀錄與統計 | 已有雛形：試算表的「題目統計」「迷思統計」。 |
| | 診斷路由 | **缺**：資料回來後，沒有規則決定學生下一步看什麼。 |
| | 教師儀表板 | 部分：試算表統計，尚無依班級、依 KC 的卡關檢視。 |

## 3. 五拍循環與元件的對應

| 五拍 | 對應元件 | 狀態 |
|---|---|---|
| 課本 | 重點卡 `content/<kc>.md` | 有 |
| 提問 | 預測題（`predict: true`） | 有，每節一題 |
| 實驗 | 探究學習單、實測數據 | 散落，未上網 |
| 虛實整合 | 互動式教具 | 有，但只有「虛」：無法輸入實測數據與模擬對照 |
| 精熟練習 | 題庫＋詳解 | 本站只做到快速檢核；精熟屬於之後的付費站 |

素養題與常見難題是五拍之後的**遷移檢驗**，不在五拍之內，而是五拍的出口。

## 4. 缺漏與建議

### 4.1 單一資料來源

同一份資料目前有多處認領：本站 `data/`、教材庫（YAML + SQLite + Streamlit）、知識圖譜、Google Classroom 流程。
建議：**正本只有一份**，其他都由它產生，不直接修改產出物。本站的 `data/` 已有完整格式與檢查腳本，是正本的候選之一。

主鍵粒度：課綱代碼是標籤，不是主鍵。KC、招式、迷思、題目各自要有穩定的內部 ID（本站的 `kc` id 與題號 `<代碼>-001` 已經是這樣做）。

### 4.2 題目屬性：角色與授權

檢核題、精熟題、常見難題、素養題、參考書題，應該是**同一個題庫格式裡角色不同的題目**，而不是五個題庫。建議欄位：

- `role`：檢核／精熟／難題／素養
- `transfer`：近遷移／遠遷移
- `license`：自編／公開考題（註明出處）／參考書（不可上公開站）

數位詳解是題目的附件，不是獨立系統；動態解析是「詳解＋互動引擎」。
參考書題與其詳解不能放進公開 repo（必守規則 4），只能在校內或之後的登入站使用。

### 4.3 共用索引補兩種節點

- **招式**：可操作的判斷規則，例如「先畫法線，角度一律從法線量」。難題與素養題要靠它掛到圖上，也是「依招式瀏覽」以訓練遷移的基礎。
- **迷思詞表**：目前 5 個題庫檔共有 70 個 `mis` 標籤，幾乎每個只出現一次（例外如「距離＝聲速 ÷ 時間」出現 3 次）。同一個迷思換個說法就會被算成不同項目，試算表的「迷思統計」無法跨題彙總。
  建議：新增 `data/misconceptions.json`（id、給學生看的說法、對應 kc），選項的 `mis` 改為引用 id。互動圖的「錯誤世界」與知識衝突點專案也引用同一份詞表。

### 4.4 資料迴路

- 作答回傳、身分（班級＋座號）、中間層（Apps Script）已定案。
- 缺：區分「選錯招式」（辨識失敗）與「選對招式但算錯」（執行失敗）的紀錄方式；規則式的診斷路由（例如命中某迷思就推薦對應的模擬或重點卡）；依班級、依 KC 的教師檢視。
- 紙本題目若要掃描分析，需印上題號或 QR code 才能對回題庫。

### 4.5 成效驗證

目前沒有設計能回答「遷移有沒有變好」。最低成本：每個招式準備一組遠遷移題，教學前後各施測一次。

## 5. 「常見難題」分頁與本站定位的衝突

本站 `CLAUDE.md` 定位為免費快速檢核站，只收 L0～L2 選擇題，L3 遷移題屬於之後的付費站。常見難題的動態解析本質上是遷移訓練，有三種處理方式：

1. **放舊站當教具**：動態解析做成互動頁放在 `CWKuo99/test`，本站各節以 `sims` 連結。不改本站定位，但「觀念 ↔ 題目」的雙向連結較弱。
2. **修改本站定位**：允許 `role: 難題` 的題目進本站，並在 `CLAUDE.md` 明訂範圍（例如只收公開考題或自編題）。
3. **等付費站**：先在本地累積，付費站上線時再放。

另一個前提：題目來源。基測與會考題可註明出處使用（建議再確認心測中心的使用規範）；出自參考書、講義、習作的題目，需要改寫成原創情境與數值才能進公開 repo。

## 6. 建議順序

1. 定 schema：KC（已有）、招式、迷思詞表、題目的 `role`／`transfer`／`license` 欄位。
2. 用**光學單元**當垂直切片，把內容層、共用索引、資料迴路全部打通一次。
3. 接上規則式路由與教師檢視。
4. 再橫向擴充到其他單元。

先做內容、後補 ID 與詞表的代價，是所有內容都要重新標註一次。
